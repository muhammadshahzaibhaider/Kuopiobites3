Closed/blocked/ambiguous payment results are recorded without logging customer details.

## Verification and release

See the PR for results at the submitted revision. Database tests use a disposable PostgreSQL 17 server with the ordered migrations, real row locks and platform schema stubs. Browser tests exercise the built app with fixture API responses. Other tests use local Express handlers, synthetic Stripe responses and database fault injection. These are complementary checks. A Stripe-hosted test transaction across the actual staging integrations remains outstanding.

Stage the additive checked_settings_save migration first, deploy backend then frontend, and check the SHA at each host. Validate one Stripe test-mode checkout through the signed webhook, kitchen notification, acceptance and tracking on the restaurant device. Validate pickup while delivery is paused and staff sign-out after a reload. Independent review and owner acceptance precede production. Roll back application versions together if needed and preserve orders, payment history and the additive functions.
